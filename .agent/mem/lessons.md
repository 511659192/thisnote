# Lessons

## 2026-10-13 — 核对创建请求正文契约
- **纠正来源：** 用户反馈笔记明细页粘贴只创建空白卡片，剪贴板文字和图片未写入卡片。
- **可核验事实：** 前端 `notePage.ts` 创建卡片请求此前发送 `contentMd`；后端 `CreateCardRequest` 的 JSON 字段是 `content`，构造器会把未提供的正文设为空字符串。
- **下次执行规则：** 对照前端请求体、后端 DTO 和服务取值字段，沿数据流检查正文是否保留；UI 命名与 HTTP 字段不同时，在调用处显式映射。

## 2026-10-13 — 上传响应使用原始字符串契约
- **纠正来源：** 用户再次指出图片上传接口仍保留 `ImageAttachmentDto`，要求直接返回字符串。
- **可核验事实：** 上传路径只有一个 `path` 字段；旧实现由 `AttachmentService.save` 构造 DTO、`AttachmentController.upload` 返回 DTO，前端再读取 `.path`。
- **下次执行规则：** 响应只承载一个字符串值时直接返回字符串；同步检查控制器、服务、前端解析与 DTO 文件，确认无残余引用。

## 2026-10-13 — 纯查询接口使用 GET
- **纠正来源：** 用户指出纯查询方法仍应使用 `@GetMapping`；此前我将查询接口统一改成了 POST。
- **可核验事实：** 本次接口调整曾把 `NoteController.list/detail`、`CardController.get`、插件列表与健康查询等纯读方法改为 `@PostMapping`；现已恢复为 `@GetMapping`，并保留路径中的查询动作名。
- **下次执行规则：** 纯查询接口使用 GET/`@GetMapping`；创建、修改、删除及其他有副作用的操作使用 POST，并在路径中标明动作。

## 2026-10-12 — 控制需求范围
- **纠正来源：** 用户要求移除未要求的 ID 迁移任务，并要求只做明确提出的功能点。
- **可核验事实：** 当前 `NotesPlugin` 不再启动 ID/数据迁移，`NoteIdentityService` 只处理标题改名；`IdFileIndex` 仅在索引文件缺失时扫描现有文件建立索引并持久化，之后按索引读取。旧 ID 迁移和插件状态重映射不再执行。
- **下次执行规则：** 用户要求 ID/文件名映射时，先实现映射和直接读写；不得自行增加存量 ID 改写、状态迁移、别名或其他迁移任务，除非用户明确要求。

## 2026-10-12 — 选择最小实现路径
- **纠正来源：** 用户指出标题更新应直接更新 NoteMeta 和文件索引，不应增加复杂协调逻辑，并询问是否是提示词不清楚。
- **可核验事实：** `NoteService.update` 已改为直接调用 `NoteRepository.saveRenamed`；`NoteIdentityService.renameTitle` 与 `CardRepository.renameFile` 目前没有其他调用点，但源码仍保留。
- **下次执行规则：** 修改前先追踪现有调用链，优先复用已有方法；除非需求明确要求，不新增协调服务、迁移、事件或状态重映射。改完后检查新增的孤立代码；涉及删文件时先说明影响并取得确认。

## 2026-10-13 — 区分页签标题与卡片标题
- **纠正来源：** 用户指出“复习 2 个页签都移除头部标题信息”指卡片上的标题信息，而不是页眉或页签信息。
- **可核验事实：** `ReviewView.vue` 将页眉（`.rv-head`）、页签导航（`.rv-tabs`）与卡片元数据（`.rv-note-title`）分开渲染；此前我删错了页眉/页签信息，保留了卡片标题。
- **下次执行规则：** UI 需求提到“头部标题”时先定位具体组件层；区分页眉、页签标签和卡片标题，不推测目标层，指代不清时先确认。

## 2026-10-13 — 明确长期复习间隔
- **纠正来源：** 用户指出记忆曲线的评分预览应为忘记轮询、困难 1 天、良好 2 天、简单 3 天；此前我根据截图误判成仅需修正 1 分钟的显示阈值。
- **可核验事实：** `SrsService.previewDue` 通过复制状态并复用 `apply` 生成预览；`ReviewView.vue` 将预览时间转换为评分按钮文案。
- **下次执行规则：** 修改记忆曲线时按用户明确给出的间隔实现；预览与实际评分必须复用同一调度规则，不从旧界面显示值推断目标规则。

## 2026-10-13 — 页签计数加载时机
- **纠正来源：** 用户指出刷新复习页时“已开启卡片”没有计数，点击页签后才显示，状态不一致。
- **可核验事实：** `ReviewView.vue` 曾只在点击“已开启卡片”页签时调用 `loadEnabledCardList()`，而计数徽标依赖 `enabledCardsLoaded`。
- **下次执行规则：** 页面展示数据计数时，应在页面进入时加载对应数据，或在加载期间明确显示占位状态；不要让计数只因用户点击页签才出现。
