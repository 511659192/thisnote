# Lessons

## 2026-10-15 — 笔记根目录以 Spring data-root 为准
- **纠正来源：** 用户澄清 `PluginDataPathUtils.configuredNotesRoot` 应依据 Spring application 配置中的 `thisnode.data-root`，而不是 `~/.thisnode/settings.json` 的 `notesRoot`。
- **可核验事实：** 插件通过 `@Value("${thisnode.data-root:${user.home}/.thisnode}")` 获取数据根目录；notes 插件另有基于 `settings.json` 的可变根目录设置及更新接口。
- **下次执行规则：** 笔记根目录统一由 Spring `data-root` 派生为 `data-root/notes`；不得再以用户 settings JSON 覆盖。调整该规则时同步处理所有插件路径及旧的根目录设置入口，不自动搬移或删除已有数据。

## 2026-10-15 — 按业务不变量精简防御分支
- **纠正来源：** 用户澄清精简代码的目的是提升可读性，删除业务上不可能的边界处理，而不是为减少行数牺牲有效保护。
- **可核验事实：** 用户明确说明配置文件存在时内容始终合规；仓库内 `pluginDataDirectory` 的调用点均传入 Spring 注入的 `FileHelper`。
- **下次执行规则：** 删除防御分支前先核对业务约束和全部调用点；移除已证实不可能的分支，保留保护真实数据风险的逻辑，不以行数减少为目标。

## 2026-10-15 — FileHelper 直接执行文件操作并处理 I/O 异常
- **纠正来源：** 用户指出 `fileWritten(Path, FileWriteOperation)` 通过回调执行写入不直观，并要求 `fileDeleted`、`fileWritten`、`fileMoved` 在 helper 内处理异常。
- **可核验事实：** JSON 对象可直接传给 `fileWritten(Path, Object)`；文本、Properties 和附件分别使用字符串或 MultipartFile 重载；所有成功的持久化重载都应发布文件事件；网盘下载先写入并校验临时文件，再以替换方式移动到目标路径。
- **下次执行规则：** JSON 对象优先使用 `fileWritten(Path, Object)`；Markdown/Properties 等文本使用 `String` 重载，附件使用 MultipartFile 重载，暂存文件使用对应重载，不传入写入回调；检查每个持久化重载都在文件操作成功后发布事件。`fileDeleted` 捕获并记录 `IOException`，失败返回 `false`；`fileWritten` 与 `fileMoved` 捕获、记录后抛 `UncheckedIOException`，保持失败可见。插件 Spring 上下文注册单例 `FileHelper`；helper 内部持有事件发布器并发布事件，业务调用方不传入发布器。

## 2026-10-15 — 通用文件变更事件覆盖插件持久化入口
- **纠正来源：** 用户指出仅监听卡片、笔记和笔记本领域事件无法覆盖所有插件文件操作，要求统一发布带操作类型和对象 URL 的文件变更事件。
- **可核验事实：** 插件持久化分散在 `JsonFileUtils`、`PropertiesFileUtils` 及 notes 的直接文件写入/移动/删除、附件操作和百度同步下载中；插件使用独立 Spring 子容器，跨插件事件需经主容器发布；SBP 的 `onPluginBootstrap` 在插件上下文 refresh 前调用。
- **下次执行规则：** 处理跨插件文件同步时先盘点所有插件的持久文件写入、移动和删除入口；在插件 refresh 前由 `FileHelper` 注册来源专属 singleton，并让 helper 持有主容器事件发布器；持久写入/删除/移动通过 helper 的配对操作方法完成，操作成功后发布带操作类型、绝对文件 URI 的事件，重命名同时携带旧 URI；临时文件与目录清理不发布；消费者按路径范围和来源过滤，不能以领域事件清单推断文件事件已全覆盖。

## 2026-10-15 — 文件变更事件不可直接触发全量同步
- **纠正来源：** 用户指出 `BaiduSyncService.requestSyncAfterChange` 触发的是全量同步，不是按事件增量处理，要求先标记 TODO 并后续实现。
- **可核验事实：** `startSyncLocked` 将 `sync` 提交到执行器；`sync` 会扫描整个笔记根目录与云端并规划全部文件变更；`FileChangeEvent` 已包含操作类型、当前 URL 和可选的旧 URL。
- **下次执行规则：** 文件事件消费者应保留并传递事件载荷；完成按事件增量同步前，只记录事件并保留 TODO，不得以全量扫描代替事件同步。

## 2026-10-15 — 日志格式请求先检查 Logback 配置
- **纠正来源：** 用户澄清“优化日志输出格式”是修改 Logback 配置，不是改业务日志消息文本。
- **可核验事实：** 项目原先没有 Logback XML 配置；Spring Boot 应用级日志级别和文件路径配置在 `backend/app/src/main/resources/application.yml`。
- **下次执行规则：** 用户要求优化日志输出格式时，先检查现有 Logback 配置并调整 appender pattern；不改业务日志消息，除非用户明确要求改消息内容。

## 2026-10-14 — 百度网盘双端比较不依赖云端 MD5
- **纠正来源：** 用户指出百度网盘返回的 MD5 不是可用于内容对比的真实 MD5，要求双端覆盖判断改用文件大小与秒级最后修改时间。
- **可核验事实：** `BaiduSyncService` 原先用本地与云端 MD5 做相等判断、变化基线和同步后状态记录；`BaiduPanClient.download` 在没有 `Content-MD5` 时还会回退使用列表 MD5。
- **下次执行规则：** 双端文件比较和持久化基线使用 `size:mtimeSeconds`；旧 MD5 基线视为缺失；下载只在存在有效 `Content-MD5` 时校验该摘要，否则校验服务端报告的大小。上传分块协议仍单独使用本地 MD5。

## 2026-10-14 — 纯重启不默认清理和构建
- **纠正来源：** 用户询问重启时清理和编译是否必要，并要求移除 AGENTS.md 中的重启构建流程。
- **可核验事实：** 本次 Maven clean 约 0.5 秒、Maven package 约 11 秒、前端构建约 5 秒；无代码变更的服务重启不需要这些构建步骤。
- **下次执行规则：** 用户仅要求重启时默认只停止并启动服务；仅在用户明确要求或确有源码/构建产物变更时构建，不默认清理产物。

## 2026-10-14 — 核验插件范围先枚举模块
- **纠正来源：** 用户在插件独立运行验证过程中将目标数量从 2 个更正为 3 个。
- **可核验事实：** `backend/pom.xml` 的模块列表包含 `memory-cycle`、`notes`、`favorite`；运行插件目录还残留旧 ID `memory-curve` 的 JAR，而当前宿主将其列为禁用状态。
- **下次执行规则：** 核验插件前先从 Maven 模块和描述符枚举当前插件，覆盖所有目标；旧 ID 构件单独报告，不混入当前模块数量。

## 2026-10-14 — 硬规则：插件改名需覆盖契约和模块身份
- **纠正来源：** 用户在 MemoryCurve 改名为 MemoryCycle 时补充指出，除业务类和显示文案外，还需同步 module 名称与 plugin-api 事件类型。
- **可核验事实：** 本次改名前，Maven 坐标和 workspace 包名仍为 `plugin-memory-curve` / `@thisnode/plugin-memory-curve`，跨插件事件仍定义为 `MemoryCurveStateChangedEvent` 并被插件监听器引用。
- **下次执行规则：** 插件全量改名必须搜索并处理插件 ID、API、资源与数据路径、Maven/PNPM module 名、plugin-api 公共事件类型及其所有消费者；同步检查物理目录、workspace 与 lockfile，并在交付前搜索旧命名。

## 2026-10-13 — 核对创建请求正文契约
- **纠正来源：** 用户反馈笔记明细页粘贴只创建空白卡片，剪贴板文字和图片未写入卡片。
- **可核验事实：** 前端 `notePage.ts` 创建卡片请求此前发送 `contentMd`；后端 `CreateCardRequest` 的 JSON 字段是 `content`，构造器会把未提供的正文设为空字符串。
- **下次执行规则：** 对照前端请求体、后端 DTO 和服务取值字段，沿数据流检查正文是否保留；UI 命名与 HTTP 字段不同时，在调用处显式映射。

## 2026-10-13 — 上传响应使用原始字符串契约
- **纠正来源：** 用户再次指出图片上传接口仍保留 `ImageAttachmentDto`，要求直接返回字符串。
- **可核验事实：** 上传路径只有一个 `path` 字段；旧实现由 `AttachmentService.save` 构造 DTO、`AttachmentController.upload` 返回 DTO，前端再读取 `.path`。
- **下次执行规则：** 响应只承载一个字符串值时直接返回字符串；同步检查控制器、服务、前端解析与 DTO 文件，确认无残余引用。

## 2026-10-13 — 纯查询接口使用 GET
- **纠正来源：** 用户指出纯查询方法仍应使用 `@GetMapping`；此前我将查询接口统一改成了 POST。
- **可核验事实：** 本次接口调整曾把 `NoteController.list/detail`、`CardController.get`、插件列表与健康查询等纯读方法改为 `@PostMapping`；现已恢复为 `@GetMapping`，并保留路径中的查询动作名。
- **下次执行规则：** 纯查询接口使用 GET/`@GetMapping`；创建、修改、删除及其他有副作用的操作使用 POST，并在路径中标明动作。

## 2026-10-12 — 控制需求范围
- **纠正来源：** 用户要求移除未要求的 ID 迁移任务，并要求只做明确提出的功能点。
- **可核验事实：** 当前 `NotesPlugin` 不再启动 ID/数据迁移，`NoteIdentityService` 只处理标题改名；`IdFileIndex` 仅在索引文件缺失时扫描现有文件建立索引并持久化，之后按索引读取。旧 ID 迁移和插件状态重映射不再执行。
- **下次执行规则：** 用户要求 ID/文件名映射时，先实现映射和直接读写；不得自行增加存量 ID 改写、状态迁移、别名或其他迁移任务，除非用户明确要求。

## 2026-10-12 — 选择最小实现路径
- **纠正来源：** 用户指出标题更新应直接更新 NoteMeta 和文件索引，不应增加复杂协调逻辑，并询问是否是提示词不清楚。
- **可核验事实：** `NoteService.update` 已改为直接调用 `NoteRepository.saveRenamed`；`NoteIdentityService.renameTitle` 与 `CardRepository.renameFile` 目前没有其他调用点，但源码仍保留。
- **下次执行规则：** 修改前先追踪现有调用链，优先复用已有方法；除非需求明确要求，不新增协调服务、迁移、事件或状态重映射。改完后检查新增的孤立代码；涉及删文件时先说明影响并取得确认。

## 2026-10-13 — 区分页签标题与卡片标题
- **纠正来源：** 用户指出“复习 2 个页签都移除头部标题信息”指卡片上的标题信息，而不是页眉或页签信息。
- **可核验事实：** `ReviewView.vue` 将页眉（`.rv-head`）、页签导航（`.rv-tabs`）与卡片元数据（`.rv-note-title`）分开渲染；此前我删错了页眉/页签信息，保留了卡片标题。
- **下次执行规则：** UI 需求提到“头部标题”时先定位具体组件层；区分页眉、页签标签和卡片标题，不推测目标层，指代不清时先确认。

## 2026-10-13 — 明确长期复习间隔
- **纠正来源：** 用户指出记忆曲线的评分预览应为忘记轮询、困难 1 天、良好 2 天、简单 3 天；此前我根据截图误判成仅需修正 1 分钟的显示阈值。
- **可核验事实：** `SrsService.previewDue` 通过复制状态并复用 `apply` 生成预览；`ReviewView.vue` 将预览时间转换为评分按钮文案。
- **下次执行规则：** 修改记忆曲线时按用户明确给出的间隔实现；预览与实际评分必须复用同一调度规则，不从旧界面显示值推断目标规则。

## 2026-10-13 — 页签计数加载时机
- **纠正来源：** 用户指出刷新复习页时“已开启卡片”没有计数，点击页签后才显示，状态不一致。
- **可核验事实：** `ReviewView.vue` 曾只在点击“已开启卡片”页签时调用 `loadEnabledCardList()`，而计数徽标依赖 `enabledCardsLoaded`。
- **下次执行规则：** 页面展示数据计数时，应在页面进入时加载对应数据，或在加载期间明确显示占位状态；不要让计数只因用户点击页签才出现。

## 2026-10-14 — Markdown、代码与富文本粘贴按来源判定
- **纠正来源：** 用户反馈 Markdown 粘贴丢失换行，随后指出粘贴代码被判成 Markdown、富文本粘贴丢失格式。
- **可核验事实：** `markdownFormat.ts` 曾在 `text/html` 前优先返回看似 Markdown 的 `text/plain`；Markdown 判定包含行内符号规则，代码中的符号可能命中；HTML 转换器只把部分语义标签转成 Markdown。
- **下次执行规则：** `.md` 文件原样读取；带结构的富文本优先转换 HTML 并保留段落与常见行内格式；代码内容不因行内符号被判成 Markdown；纯文本保留换行后再按结构语法判定。

## 2026-10-14 — 区分批量上传与批量文件管理
- **纠正来源：** 用户指出逐文件调用 `panClient.upload` 和本地多线程都不等于远端批量上传 API；随后明确授权采用 8 个线程、256 队列的非阻塞本地并发方案。
- **可核验事实：** `BaiduPanClient.upload` 按单个目标路径执行 `precreate`、文件分片上传和 `create`；文件管理 API 对移动、删除操作限制每次最多 50 项；上传工作池使用 8 个线程和容量 256 的有界队列。
- **下次执行规则：** 评估批量上传时区分远端批量 API 与本地并发；不得将批量移动、分组循环或并发请求称为单请求批量上传。上传任务不按 50 项切组，由有界线程池和队列控制提交；50 项分批仅用于 API 明确限制的文件管理操作。只有用户明确选择本地并发时，才按授权规格实现非阻塞异步任务。

## 2026-10-14 — 区分后端源码与运行中 API 版本
- **纠正来源：** 用户反馈新增的“双端一致”统计在界面显示为空；此前我确认了源码计算和展示，但没有确认运行中接口是否返回新增字段。
- **可核验事实：** `BaiduSyncService.preview()` 计算 `consistentCount`，`BaiduSyncPreview` 定义该响应字段；截图中统计标签存在但数值缺失，无法仅凭截图确认运行中的后端版本。
- **下次执行规则：** 增加后端响应字段后，分别说明源码状态与运行状态；未获授权构建或重载时，不声称运行界面已经呈现新值。前端对旧响应缺少字段时显示明确的不可用提示，不留空或伪报 0。
